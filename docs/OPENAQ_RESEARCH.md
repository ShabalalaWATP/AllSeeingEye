# OpenAQ air-quality research

The operator's OpenAQ key was verified against the official v3 API on
11 September 2026. It is stored only in ignored `backend/.env` under
`ASE_OPENAQ_API_KEY`. Compose installations read the root environment instead.
The key belongs on the server; do not put it in frontend configuration.

## Operator flow

Open **Research area** from the map's right toolbar, draw the area, choose a
period and check sources. The OpenAQ capability collects a bounded sample of
station observations when selected. It does not add background polling or
automatically enable another map overlay. Report generation still requires a
working administrator-configured AI connection.

The area bounding box is disclosed to OpenAQ. The question and exact boundary
are not sent to this provider. Station discovery is followed by exact local
polygon membership checks and the requested measurement-time interval. Missing
credentials, inaccessible data and empty results have distinct coverage receipts.
See the [area research workflow](AREA_RESEARCH.md).

## Data contract

OpenAQ aggregates station measurements from original providers. A station's
latest activity timestamp does not establish that every sensor is current.
Each accepted observation needs its own measurement date, parameter, units,
station and sensor identifiers, and original attribution. No unit conversion,
AQI, health classification or continuous pollution surface is inferred.

The latest endpoint returns the last value in each sensor's series, not every
measurement within an interval. Late-arriving historical readings may not appear
there. See the [latest resource](https://docs.openaq.org/resources/latest) and
[location latest operation](https://docs.openaq.org/api/operations/location_latest_get_v3_locations__locations_id__latest_get).

Dataset permissions vary. OpenAQ exposes commercial-use, redistribution,
modification, attribution and share-alike fields through its licence resource.
Preserve the applicable licence and upstream provider credit when evidence is
frozen into reports. A source excluded by the licence policy is a collection gap,
not a statement that its measurements are wrong.
[OpenAQ licence metadata](https://docs.openaq.org/resources/licenses).

## Collection and reuse bounds

- One page of at most 100 station candidates, followed by at most three Quick or
  six Detailed station queries and four distinct licence lookups. Selection
  prioritises station activity within that page; it cannot promise the newest
  stations across the whole catalogue.
- At most 50 latest observations per selected station, with exact boundary and
  acquisition-time checks. Mobile stations, missing units/unsupported parameters, invalid
  readings and measurements outside the requested interval are excluded.
- Ten-second Quick and eighteen-second Detailed deadlines preserve observations
  already accepted when later work cannot finish. Closing/cancelling research
  still cancels the collection operation.
- The global research request counter admits source tasks. This capability can
  use up to eleven HTTP requests per admission, disclosed in its source preview
  and receipt. There are no retries, background polling or raw-data archives.
- Shared two-second request spacing and a rolling 1,800-request hourly cap apply
  within the single API process. Failed requests consume allowance and trigger
  a sixty-second cooldown. Licence metadata is reused only within the current run.
- Evidence is admitted only when applicable licence metadata explicitly permits
  commercial use, redistribution and modification, with no share-alike obligation.
  Required attribution must be present. Missing, restricted or unsupported terms
  produce an explicit coverage gap; they are not silently treated as permissive.

Evidence keeps the sensor/station identity, source-reported observation point,
pollutant, original units, measurement timestamp, provider/owner and applicable
licence credit. The full evidence summary carries licence links and dates into
report exports. Reliability remains unassessed; the collector is not a second
independent source for the originating station's reading.

## Service limits

OpenAQ documents a free-key allowance of 60 requests per minute and 2,000 per
hour. The allowance is shared by everything using the same key. Multiple app
processes or other clients need shared operational budgeting; adding another
process does not grant another allowance.
[OpenAQ rate limits](https://docs.openaq.org/using-the-api/rate-limits).

Credentials are sent in an origin-bound `X-API-Key` header. Requests must retain
the app's DNS validation, size bounds, timeout and no-redirect protections.
[OpenAQ authentication](https://docs.openaq.org/using-the-api/api-key).
