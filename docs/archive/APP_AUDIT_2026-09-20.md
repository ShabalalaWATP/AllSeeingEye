Audited revision: `a88359e7376a1e5bd0c1a0a008975a3ba769ad86`.

This is a report-only audit. Ten code/workflow defects were identified through
targeted local reproductions and source tracing. No application code, production
data, credentials or configuration was changed. Findings describe reachable
behaviour; they do not claim that every failure has already occurred in production.

## Recommended repair order

Start with the board authorisation race, duplicate run admission and stalled
subscription recovery. Then repair report scope, requirements and subscription
history preservation. Finish with library navigation, map controls and team
reactivation safeguards. All ten findings are P2: actionable defects needing
correction, with their specific triggers and limits below.

## 1. A revoked team member can finish saving a board post

**Trigger:** A post request passes its authority check, the member is removed in
another request, then the original request finishes saving.

**Impact:** A post can commit after the author has lost membership. This is a
concurrent authorisation failure, not evidence that an already removed member
can start arbitrary new requests successfully.

**Cause:** `backend/src/ase/application/teams/board_access.py:36` reads authority
without the shared administration guard or account/team locks. Creation at
`backend/src/ase/application/teams/board.py:101` subsequently commits using that
earlier result. The route and container wiring do not supply an enclosing guard.

**Evidence:** A local file-backed SQLite test paused creation after its check,
removed the member through the real team service on a separate connection, then
resumed creation. It confirmed both absent membership and a persisted post.

**Repair:** Serialise authority-changing operations and board mutations using the
existing guard and ordered locks, reload authority, and retain protection through
commit. Add equivalent coverage for editing and moderation, which share the helper.

## 2. Retrying a brief run after a lost response can duplicate research work

**Trigger:** Click **Run once** on a saved brief. The server admits the job but the
response is lost. The UI reports an error, enables the action again, and the user
retries.

**Impact:** The retry can admit another job for the same brief revision, causing
duplicate reports and potentially additional provider charges.

**Cause:** `frontend/src/lib/api/researchBriefs.ts:89` creates a new request UUID
on every invocation. `frontend/src/components/research/BriefEditor.tsx:105`
allows another attempt after an error. Server deduplication in
`backend/src/ase/application/report_jobs/service.py:94` is keyed by owner and
request UUID, so it cannot recognise this retry as the original attempt.

**Evidence:** Executed the actual client function with an injected lost-response
stub. Two attempts for the same brief/revision used different IDs. Server
admission behaviour was traced in source; no real duplicate charge was incurred.

**Repair:** Retain one request ID for an unresolved attempt and reuse it on retry.
Allocate a fresh ID after confirmed success or an explicit new run. Cover a lost
response after admission and assert only one job exists.

## 3. Pausing during automatic retry can leave a resumed subscription stuck

**Trigger:** Pause a subscription while its edition is waiting for retry. Let the
retry timer fire, then resume the subscription.

**Impact:** The subscription becomes enabled again but its edition remains
paused, and that active edition blocks later scheduled admissions.

**Cause:** `backend/src/ase/container/subscription_schedule_controls.py:35`
does not pause `RETRY_WAIT` editions. Retry orchestration at
`backend/src/ase/container/subscription_retry_orchestration.py:319` requeues the
job without checking schedule activation. The worker correctly refuses to run a
disabled schedule, but the resulting `PAUSED/provider_error` state is not one
the resume path recognises as `schedule_paused`.

**Evidence:** A local SQLite test using the actual admission, retry, control and
worker-gate services produced:

```text
After retry timer: schedule disabled; edition queued; job queued
After resume: schedule enabled; edition paused; reason provider_error; job paused
```

**Repair:** Include retry-wait editions in pause/resume transitions, preserve their
resumable checkpoint, and have retry admission respect current schedule activation
under the existing guards.

## 4. A regional follow-up silently loses its geographic restriction

**Trigger:** Save region-only research, for example Europe with no separately
selected countries, and start a follow-up.

**Impact:** The follow-up retains parent evidence but its new collection request
loses the regional restriction. Its scope can become worldwide.

**Cause:** `frontend/src/lib/followUpScope.ts:113` does not preserve `regions`.
`backend/src/ase/application/reports/followup_scope.py:57` validates countries,
area and dates but does not compare regions.

**Evidence:** The actual frontend helper returned no regions and an empty country
list for a Europe-only saved scope. A separate backend reproduction built a real
`ReportRequest`, saved it through `report_scope`, and passed an unrestricted child
to the real guard:

```text
saved_regions=['europe']; saved_countries=[]
followup_regions=(); scope_guard=accepted
```

**Repair:** Validate and preserve normalised regions on both sides. Cover region-only
requests and requests combining regions with individual countries.

## 5. Regenerating a brief report drops its requirements and brief reference

**Trigger:** Generate a report from a Research Brief containing intelligence
requirements, then select **Regenerate** in report management.

**Impact:** The regenerated analysis no longer receives those authored
requirements, and its version loses the exact brief provenance. The regenerated
report can therefore answer a less specific task than the original.

**Cause:** `backend/src/ase/application/reports/generate.py:211` rebuilds a request
from root scope before loading the previous version. Requirements live on the
version and are not restored. The brief-reference attachment in
`backend/src/ase/container/report_job_execution.py:93` belongs to the queued path,
which regeneration bypasses.

**Evidence:** An isolated pytest used the real container, database and regeneration
service, intercepting production before model work. The previous version contained
requirement `IR1` and brief revision 3; the production job had
`canonical_requirements=()`. Missing brief attachment was verified by source tracing.

**Repair:** Restore frozen requirements and exact brief provenance from the saved
version, or use the brief-aware execution path. Test both generation inputs and
newly saved version metadata.

## 6. Brief subscriptions discard their previous-report context

**Trigger:** A brief-linked recurring subscription has an existing baseline and
retained content signatures, with repetition avoidance enabled.

**Impact:** Later editions lose the previous-report context used for comparison
and repeat suppression. They can repeat material and lack the intended comparison
with the previous edition.

**Cause:** The brief branch in
`backend/src/ase/application/schedules/revision_snapshot.py:45` creates a request
without copying `schedule.baseline_report_id` or `seen_content_signatures`. The
older schedule branch does copy these fields. Downstream baseline selection at
`backend/src/ase/application/schedules/subscription_prepare.py:193` receives none.

**Evidence:** A Python reproduction using real domain objects and snapshot
round-tripping compared otherwise equivalent schedules:

```text
Brief-linked: baseline retained=False; seen signatures=()
Legacy:       baseline retained=True;  seen signature count=1
```

The context loss was executed locally; downstream report-quality consequences
were traced in code, not measured through a billed model run.

**Repair:** Preserve subscription history in brief-derived requests without
overwriting authored settings or changing analytical compatibility unnecessarily.

## 7. Saved briefs beyond the first 50 are unreachable through the library

**Trigger:** A user has access to more than 50 briefs.

**Impact:** Items outside the first page cannot be found through **My briefs** or
**Choose a saved brief**, unless the user already has a direct link. The records
are not deleted.

**Cause and evidence:** `frontend/src/lib/api/researchBriefs.ts:23` always fetches
`limit=50`; `frontend/src/components/research/BriefLibrary.tsx:30` renders that
single page without pagination or search. The server supports offsets at
`backend/src/ase/api/routers/research_briefs.py:39`. This is a confirmed static
fetch/render omission, not a production test with 51 records.

**Repair:** Add pagination or **Load more**, retaining access-change invalidation.
Test that the 51st accessible brief can be reached from both entry points.

## 8. Unrelated live updates dismiss selected news articles

**Trigger:** Select a news marker present only in the separate news snapshot.
An unrelated live event, such as an aircraft observation, then arrives.

**Impact:** The article inspector closes even though the article and marker remain
available.

**Cause:** `frontend/src/features/globe/useDashboardEvents.ts:41` merges the news
snapshot with the main event store, but `frontend/src/stores/events.ts:223` clears
selection based only on the narrower store's membership.

**Evidence:** A no-network reproduction loaded the real store through Vite SSR,
selected a supplemental article ID, then inserted an unrelated aviation event.
`selectedId` became `null`.

**Repair:** Make selection ownership consistent with the combined visible records.
Preserve correct invalidation when the article actually disappears or access changes.

## 9. Conflict regions can appear enabled while no layer is rendered

**Trigger:** Hide the Conflict category, then enable **Conflict regions** through
the map guide.

**Impact:** The switch reports that regions are on, but nothing is rendered.
Toggling that switch cannot restore the hidden parent category.

**Cause and evidence:** `frontend/src/features/globe/mapGuideControls.ts:56`
reflects only `showRegions`, while rendering at
`frontend/src/features/globe/useConflictRegionSelection.ts:29` also requires the
parent category. A reproduction called the real guide-switch function with Conflict
hidden and confirmed an on state with a false rendering condition.

**Repair:** Reflect effective visibility and enable the required parent when the
user switches regions on, or explain why the control is unavailable.

## 10. A team can be reactivated without an active Manager

**Trigger:** Archive a user-created team, deactivate its sole Manager, then
reactivate the team as an administrator.

**Impact:** The team is active with no active Manager. Normal roster management
requires administrator intervention; this is not an irreversible lockout.

**Cause:** `backend/src/ase/application/teams/service.py:131` sets the active state
without checking the active-manager invariant.

**Evidence:** A local test ran the real team and account-management services for
that sequence and confirmed an active-manager count of zero after reactivation.

**Repair:** Require an active Manager before reactivation, with an atomic
administrator recovery path for appointing one.

## Subsequent remediation

Alex requested implementation after the report above. The follow-up branch
`codex/app-audit-fixes` addresses all ten findings with behavioural regressions:

- Board mutations acquire the existing administration, account and team locks
  before their authority decision. Archived read tracking remains available.
- Brief retries retain an unresolved client request ID. Server replay recognises
  the immutable brief revision before recalculating a relative observation window,
  including concurrent admission. Explicit request digest checks remain enforced.
- Subscription pause includes retry-wait editions. Retry admission rechecks current
  activation under the established guards, and due selection excludes inactive
  schedules before applying its batch limit.
- Follow-ups retain normalised regions in collection, form state and displayed scope.
- Regeneration restores frozen requirements and exact brief provenance; an ordinary
  follow-up does not inherit its parent's brief identity.
- Brief subscriptions preserve their baseline and retained signatures without
  changing analytical compatibility merely because execution history changed.
- Brief libraries expose bounded page navigation, retry and access-change resets.
- Dashboard selection validates the combined visible records; explicit expiry,
  filtering and changed access still clear selections.
- Conflict-region switches reflect effective visibility and enable their parent
  category when required.
- Reactivation requires an active Manager. Administrators can explicitly appoint
  another active account in the same transaction, with roster limits and existing
  self-membership protections retained.

Application policy stays in application services, persistence queries in adapters,
and asynchronous UI state in focused hooks. The existing architecture contracts,
generated API types and source-file limits remain the checks for these boundaries.
There is no schema migration, new dependency or production infrastructure change.

Focused tests cover the reproduced failures, legitimate controls and SQLite/PostgreSQL
concurrency. Independent review identified and prompted the bounded retry-queue
correction above. Final full-suite and security-check evidence belongs to the
associated pull request, separate from the original audit's green baseline CI.

Existing editions already stranded with a provider error are not automatically
replayed. Use the edition's explicit Resume action after reviewing its saved state.
Production AI connection setup still requires an operator-selected provider/model
and credentials. No live model quality or fresh source-health claim follows from
these offline regressions.
